# Domain docs

This repository has one domain context. Read `GLOSSARY.md` for vocabulary and the relevant ADRs under `.agents/adr/` before changes to skill behavior, invocation, or distribution. Preserve the existing locations.

Use glossary terms in issues, specs, tests, and implementation. If a term is unclear or a proposed behavior conflicts with an ADR, use `domain-modeling` to resolve the decision before writing it as settled guidance.

Missing domain documents do not block routine work. Create glossary entries or ADRs only when the work resolves a term or a consequential design tradeoff.
